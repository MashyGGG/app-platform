## 1. 需求与动机

- **用户故事**：As **一个想提升英语口语的学生**（不限考试），I want **打开 App 10 秒内就能开口说话，说完立刻拿到一个我能马上再做一次的纠正，并且知道今天可以停**，so that **我每天愿意练口语**，而不是面对一堆菜单或一张看不懂的分数图。
- **为什么做独立日练产品，而不是在现有多模块口语平台上加一项**
  - 多模块口语平台常见形态：入口按模块铺（E1）、日练靠任务编排但落地仍是多模块（E5）、短练习出分前被 loading / 跳页堵住（E2）。
  - 市场上单点很强但都只有一半：ELSA 只纠音（E7）、Speak 只聊天（E8）、Duolingo 很少真开口（E9）。
  - 空隙就是：**短开口 + 一个可执行下一步 + 明确收工**。这需要一条路的信息架构，**不可能靠在模块墙上再加一项达成**。
  - **时效性提醒（E18，v1.1 新增）**：这个空隙不是静止的——SpeakShark 这类新产品已经在把「纠音」和「对话」缝合到一起。本产品真正能守住的护城河不是「既纠音又能聊」本身，而是**一个问题 + 强制收工 + 去关卡化**这套更激进的简化（principle 1、4），这一点必须在任务分解阶段被工程团队理解为"为什么克制"，而不是被当成"功能不够"去补齐。
- **为什么必须同时写基建**：学生端的「再读这 3 个音 / 换一种说法」不是算法，是**内容**（题、示范音、词+音素、paraphrase）。关卡词库照搬会把关卡与解锁带回来（E4）。所以基建也分 MVP / Next 裁剪。

## 2. 产品原则（约束后续所有范围，违反即驳回）

1. **一条路，不选模块。**（E1、E9、E23）
2. **下一步必须当屏可完成。** 「去看报告 / 等通知 / 去词库」都不算下一步。（E2、E7、E15）
3. **短任务同步反馈；长任务才异步。**（E2）
4. **一个问题优于七维雷达。**（E7、E8、E22）
5. **基建只服务主循环。** 学生这一拍用不到的内容模型，不进本阶段。（E4、E16）
6. **独立栈：新库、新登录、新后端。**（E17-2、E17-3）
7. **克制是护城河，不是缺陷。**（E18、E19、E21，v1.1 新增）本产品在功能数量上永远比不过 ELSA/Speak/Praktika/流利说；任何"加一个选项/加一条反馈"的提案，必须先证明它不会破坏原则 1 和 4，而不是默认"多总比少好"。

# 第一部分：MVP

**MVP 成功标准**（四条同时成立，依据 E9、E15；v1.1 未变更）

1. 打开 App 后 **10 秒内可开始说话**（**含首次麦克风授权**，E17-4）。
2. 说完后 **同一屏**出现一个可执行动作，且能当屏再录。
3. 当天有 **「今天练完了」** 状态（再试可跳过，E17-5）。
4. 连续 7 天使用后，产品能用**一句模板文案**说出学生的变化（E17-6）。

## 4. MVP 学生端 — 做什么 / 为什么 / 怎么做

### 4.1 做什么（一场 8 分钟会话，五拍）

| 拍 | 功能 | 学生看到 | 明确不做 |
|---|---|---|---|
| P0 进入 | 首页 = **今日一题** | 题目 + 一个录音键 | 侧栏、模块墙、课程列表 |
| P1 热身（可选） | 听示范 → 跟读**一句** | 「先跟着说」开关，默认关 | 独立初级模式/独立页面 |
| P2 主开口 | **30–90 秒**表达观点+理由 | 计时、随时停 | 多人房、自由多轮闲聊 |
| P3 下一步 | **只一个问题** + 当屏再试 | 一句人话 + 可播放材料 | 雷达图、跳转报告页 |
| P4 收工 | 「今天练完了」 | 完成态 + 7 天一句 | 排行榜、积分商店 |

**P3 只允许三类**（系统只挑一个赢家）

| 类型 | 何时判为它 | 当屏动作 | 依赖基建 |
|---|---|---|---|
| **A 听不清** | 音素/识别置信最差 | 再读 **≤3 个**词 | word + IPA + 示范音 |
| **B 在背稿** | 像念稿、用词单一 | 给一句换说法，再说一遍 | paraphrase sentence |
| **C 没说完** | 有观点无理由/例子 | 提示补一句再结束 | prompt.checklist |

优先级 **A > B > C**（听不清时先纠音，否则换说法没意义 —— E7）。UI **只展示赢家**（原则 4、E22）。

### 4.2 为什么（逐条挂依据）

| 决策 | 依据 |
|---|---|
| 首页就是今日题，不选模块 | E1（多入口=决策成本）、E9（打开即练）、E23（ELSA 加模式选择反而验证了这个代价） |
| 题型是「观点+理由」独白，不是单词跟读 | 只跟读会退化成 ELSA 子集（E7）；泛学生要的是能表达（E8、E17-1） |
| 热身是同一题的可选拍，不是新模块 | E15（敢开始）；有稿可依的跟读已被课堂跟读类产品验证（E3、E12）；做成模块就回到 E1 |
| 一个问题 + 当屏再试 | E7 的核心循环；E2 证明等待/跳转会杀掉再试；E22（Yoodli）证明多维反馈会稀释可执行性 |
| 主路径同步出分，不登记异步任务 | 音频短（E3 词/句 PA 本就快）；E2 的异步是为长任务设计；弱网降级见 §4.3、AC-S10 |
| 显式收工 + 允许跳过再试 | E9（允许停）；E17-5（避免卡死导致当天无法完成） |
| 7 天进步用模板 | E17-6；模板可 pass/fail 测（LLM 文案不可测，违反验收要求） |
| 泛学生题材（生活/校园/观点），不绑 DSE 题型 | E17-1；E11 的应试格式属 Future |
| 不做 streak/排行榜/头像形象包装 | E9、E19、E20：低门槛包装（头像/连续打卡）已被验证有效但代价各异（Praktika 反馈变浅、Duolingo 驱动力偏焦虑）；本产品赌「纠正质量」本身，需 Next 门槛前用真实留存数据验证这个赌注 |

### 4.3 怎么做（学生端 MVP）

**信息架构（无侧栏）**

```
/today            唯一主页 = 今日会话（登录后默认落地）
/today/result     可深链；但「再试」仍在会话内，不新开报告产品
/me               7 天模板句 + 完成日历（只读）
/auth             邮箱即用（见 4.4）
```

**会话状态机**（显式状态才能做收工/重录；但 MVP **同步**，不引入 async_task）

```
NOT_STARTED → WARMUP? → SPEAKING → SCORING → RETRY → COMPLETED
                                      └ 失败 → FAILED（可重录 P2，当天资格不丢）
                                      └ 超时/弱网 → DEGRADED（v1.1 新增，见下）
RETRY 可被 SKIPPED → COMPLETED（E17-5）
```

**评分流水线（怎么得出「一个问题」）**

1. 上传短音频 → 对象存储（**播放用压缩格式**，评分用未压缩/16k）。依据 E3。
2. ASR 转写。
3. Azure PA：
   - 热身跟读 / A 类再读 → **有参考文本**，走 phoneme 模式（最稳，E3）。
   - P2 自由说 → PA 对自由说弱于朗读（E3），因此 A 类候选先取 **prompt 预挂词命中**，再退化到 ASR 低置信词。
4. 小 LLM 只做两件事：**三选一分类** + **一句人话教练语**。不产出多维分数。
5. 规则层决定赢家（A>B>C），UI 只显示赢家。

**弱网 / 超时降级（v1.1 新增，依据 E2 + 真实移动网络场景）**

- P2 提交后若评分链路（ASR+PA+小 LLM 三跳合计）**超过 20s** 未返回，客户端 SHALL 展示「网络有点慢，你可以先跳过再试，或稍后在本会话内重试」，**不强制用户干等**，不消耗当日完成资格。
- 状态机进入 `DEGRADED`：允许 (a) 跳过再试直接 `COMPLETED`，或 (b) 保留 pending 请求、结果返回后仍可当屏展示（若用户还在页面）。
- 与 AC-S6（评分失败/500）的区别：AC-S6 是**接口报错**，本条是**接口未报错但变慢**——两者都不能让用户卡死，但降级文案不同，不应合并成一个状态，否则「弱网」会被误判成「失败」，影响埋点准确性。
- 对应验收标准见 **AC-S10**。

**「马上」的可测定义**

| 指标 | 目标 | 依据 |
|---|---|---|
| 首页 → 可录音（含首次授权） | **≤ 10s**（E17-4） | 成功标准 1 |
| P2 提交 → P3 出现 | 目标 **≤ 8s**，P95 ≤ 15s；**超 20s 触发降级提示**（v1.1） | E2（等待即流失）、E7（即时钻） |

授权做法：**进 `/today` 不弹权限**；点录音键时才请求一次；拒绝后给「需要麦克风才能练」并可重试。（把授权算进 10s，所以流程必须是「一次点击 → 授权 → 直接开录」，不允许多层弹窗。）

**收工与 7 天句（纯模板，E17-6）**

- 完成条件：再试成功 **或** 跳过再试 → `COMPLETED`，写 `daily_completion(date, session_id, winner_type, retry_state)`。
- 7 天句从最近 ≤7 条 `winner_type` 计数生成，模板固定，例如：
  - A 最多 → 「这周你主要在练**把话说清**（7 天里 4 次）。」
  - B 最多 → 「这周你主要在练**用自己的话说**（7 天里 3 次）。」
  - C 最多 → 「这周你主要在练**把理由说完整**（7 天里 3 次）。」
  - 不足 3 次完成 → 「先连着练 3 天，我就能告诉你变化。」
- **不调用 LLM**，因此可写 pass/fail 测法（见 AC-S8）。

### 4.4 MVP 登录（邮箱即用，E17-3）

- 输入邮箱 → 发送 6 位一次性码（或 magic link）→ 登录成功即建账号。**无密码、无学校绑定、无邀请码。**
- 后端自建独立 token 体系（E17-2）。
- 为什么：泛学生自助注册（E17-1）；密码/学校流程会挡住首日转化（对照 E9 的「先给价值再要账号」）。
- 妥协记录：邮箱即用意味着**同一人换设备靠邮箱找回**，MVP 不做手机号/第三方登录。

### 4.5 MVP 学生端明确不做

多人房、实时多轮语音对话、DSE 10+8 钟、词库首页、脚本库、通知中心、订阅墙、老师任何入口、口音选择（v1.1 备注：SpeakShark 把口音选择做成卖点，E18；MVP 阶段仍不做，理由是泛学生首日更需要"能不能被听懂"而非"哪种口音"，口音差异化留待 Future 评估）。依据 E16、E11、E4、§3。

## 5. MVP 基建 — 做什么 / 为什么 / 怎么做

基建 = **让 P0–P4 每天出得来题、纠得出音、给得出换说法** 的最小内容层。不是闯关词库，不是可视化 CMS（E4）。

### 5.1 做什么（四个对象 + 一个导入口）

| 对象 | MVP 字段（最小） | 用在哪 | 故意没有 |
|---|---|---|---|
| **Prompt（今日题）** | id、题干、`warmup_sentence`、`model_audio`、`checklist`（理由/例子）、`sort`、`is_active` | P0/P1/P2/C | 课程树、单元、解锁、年级体系 |
| **Word（纠音词）** | 词形、IPA、`phonemes`、示范音、可选释义 | P3-A | 关卡、积分、猜词游戏 |
| **Sentence** | 文本、示范音、`prompt_id`、`kind=warmup\|paraphrase` | P1、P3-B | 用户自建长课文、公共脚本分配 |
| **Session** | 用户、prompt、音频、转写、`winner_type`、`retry_audio`、`retry_state`、完成时间、**`degraded_flag`（v1.1 新增，记录是否触发弱网降级）** | P3/P4、7 天句、NFR 可观测 | 多模块 feature 进度 |

**内部导入（运营 MVP）**：CSV / JSON 批量导入即可，**不做可视化 CMS**。
首批要求：**21 道题（=3 周不重复）**，每题绑 **3–5 个易错词** + **1–2 句 paraphrase** + **1 句热身句** + **示范音**。

**每日出题规则**：`dayIndex % N` 轮转 + 用户维度「最近 7 天不重复」。**不做推荐引擎**（E9 要的是稳定每日任务）。

### 5.2 为什么（基建为何这么瘦）

| 决策 | 依据 |
|---|---|
| 必须有 Prompt | 空白麦学生不知道说什么；E8 的对话产品也靠情景 |
| 必须有 Word+IPA+示范音 | 否则 A 类只剩「你发音不准」空话；ELSA 的差异正在具体音（E7）；词级 PA 已验证（E3） |
| 必须有 paraphrase | B 类当屏动作的材料；复用课程化句子资产会带回关卡心智（E4） |
| 必须有 Session 主键 | 没有会话记录就没有收工与 7 天句（E9、E15）；练习塞进单条 JSON 数组会导致无法回溯与异步（E2）——第一天就要主键 |
| 不做闯关词库 / SRS / 课程 | SRS 要跨日队列 → Next（E10）；关卡会重建模块墙（E4、E21：流利说的关卡+多维分数是反面教材） |
| 不做老师 CMS | 老师不是 MVP 用户（§3） |
| 21 道起步 | 3 周足够验证留存（E9）；不够再扩，避免先造内容工厂 |
| Session 新增 `degraded_flag` | 不加此字段就无法区分「弱网变慢」和「真实评分失败」，NFR 可观测性会失真（v1.1，见 §4.3） |

### 5.3 怎么做（基建 MVP）

**数据模型（新库；不要把练习塞进单条 JSON 数组 —— 对照 E2 的教训）**

```sql
prompt(id, text, warmup_sentence, model_audio_key, checklist_json, sort, is_active)
prompt_word(prompt_id, word_id)          -- 预挂易错词，A 类首选候选
word(id, lemma, ipa, phonemes_json, audio_key, gloss)
sentence(id, prompt_id, text, audio_key, kind)   -- warmup | paraphrase
speaking_session(id, user_id, prompt_id, status, audio_key, transcript,
                 winner_type, winner_payload_json,
                 retry_audio_key, retry_state, completed_at,
                 degraded_flag)                  -- v1.1 新增：本次是否触发弱网/超时降级
daily_completion(user_id, date, session_id, winner_type, retry_state)
app_user(id, email, created_at)           -- 邮箱即用（E17-3）
```

**学生 API**

| 方法 | 路径 | 行为 |
|---|---|---|
| POST | `/auth/code` | 发送邮箱一次性码 |
| POST | `/auth/verify` | 校验并签发 token（首次即注册） |
| GET | `/today` | 今日 prompt + 热身素材 + 当日 session（若有） |
| POST | `/today/sessions` | 创建/取回当日 session（**同用户同日幂等一条**） |
| POST | `/today/sessions/{id}/audio` | 上传 P2 音频，**同步**返回 `{winnerType, coachLine, retryItems[]}`；**超 20s 未返回时客户端本地触发降级 UI（见 §4.3），接口本身仍继续处理，返回后若用户仍在页面则照常展示** |
| POST | `/today/sessions/{id}/retry` | 上传再试音频 → COMPLETED |
| POST | `/today/sessions/{id}/skip-retry` | 跳过再试 → COMPLETED（`retry_state=SKIPPED`，E17-5） |
| GET | `/me/week` | 7 天模板句 + 完成日历 |

**运营 API**：`POST /ops/import`（内网 + 运营角色）。不做权限矩阵产品。

**A 类词从哪来（两级策略）**

1. **主路径**：命中 prompt 预挂词 → 有 IPA 和示范音，PA 有参考文本（最稳，E3）。
2. **降级**：预挂词全未命中 → 取转写中 PA/置信度最差 ≤3 词，临时建 Word；**无示范音则 TTS**。
   - 为什么要降级：全预挂会漏；全动态会「只出红词、没有示范音」，反而伤 E7 的信任。TTS 是降级手段，不是品质目标。

**音频约定**

- 题目示范音**预录**优先（E7、E12 的跟读产品都用标准音）；词的示范音允许 TTS 兜底。
- 学生音频：短文件同步处理，存 key + 时长；播放/评分格式分离（E3）。

**工程实现建议**（通用最佳实践）

- 发音评估优先使用「有参考文本」的音素模式（E3）。
- 音频做播放/评分双格式分离（压缩格式给播放，未压缩/16k 给评分）（E3）。
- 练习记录采用显式状态机 + 显式失败态，确保重试与可观测性可收敛。
- **不做**：关卡/解锁/积分词库（E4）、把「今日任务」拆回多模块入口（E5）、课堂多人语音管线（E6）、复杂权限菜单产品（E17-2、E17-3）。

## 6. MVP 验收标准（EARS · 每条可 pass/fail）

**学生端**

- **AC-S1**：WHEN 已登录学生打开 App，THE 系统 SHALL 展示今日题目与录音控件，且不展示任何模块/菜单列表。 · 测法：`/today` DOM 无导航菜单项。
- **AC-S2**：WHEN 学生首次点击录音键，THE 系统 SHALL 在一次点击内请求麦克风授权并在授权成功后直接开始录音，且从进入首页到开始录音 ≤10s。 · 测法：埋点 `home_to_recording_ms ≤ 10000`（首次安装场景，含授权弹窗）。
- **AC-S3**：WHEN 学生提交 30–90s 主开口，THE 系统 SHALL 同屏返回**恰好 1 个** `winnerType ∈ {A,B,C}` 及可执行 `retryItems`。 · 测法：响应 JSON 只含一个 winner；UI 无第二条纠正。
- **AC-S4**：WHILE 展示下一步，THE 系统 SHALL 允许不离开当前会话再次录音。 · 测法：再试过程无路由跳转到独立报告页。
- **AC-S5**：WHEN 再试成功 **或** 学生选择跳过再试，THE 系统 SHALL 将当日会话标为 COMPLETED 并展示收工文案。 · 测法：跳过后 `retry_state=SKIPPED` 且 `/today` 返回已完成态。
- **AC-S6**：IF 评分失败（接口报错），THEN THE 系统 SHALL 保留今日题目并允许重录主开口，不得消耗当日完成资格。 · 测法：注入 500 后仍可重录并完成。
- **AC-S7**：WHERE 学生打开热身，THE 系统 SHALL 播放示范并接受一句跟读，且跳过热身不影响进入主开口。 · 测法：两条路径都能到 P2。
- **AC-S8**：WHEN 学生查看 `/me`，THE 系统 SHALL 展示由最近 ≤7 条完成记录**按固定模板**生成的一句进步文案，且不调用 LLM。 · 测法：构造 4A/2B/1C → 文案等于「把话说清 … 4 次」模板；日志无 LLM 调用。
- **AC-S9**：WHEN 新用户输入邮箱并校验一次性码，THE 系统 SHALL 直接创建账号并进入 `/today`，不要求密码或学校信息。 · 测法：全新邮箱走通到落地页。
- **AC-S10**（**v1.1 新增**）：IF 评分链路（ASR+PA+小 LLM）响应超过 20s 但**未报错**（弱网/服务变慢），THEN THE 系统 SHALL 展示「网络有点慢，可以先跳过再试或稍后重试」提示，且不消耗当日完成资格，不得让用户处于无提示的无限等待。 · 测法：模拟评分接口延迟 25s 且最终返回 200，UI 在第 20s 出现降级提示；`degraded_flag=true` 被记录；用户可选跳过直接 COMPLETED。

**基建**

- **AC-I1**：THE 系统 SHALL 拒绝上架缺少 `warmup_sentence` / `model_audio` / ≥1 paraphrase / ≥3 预挂词的 prompt。 · 测法：导入校验报错。
- **AC-I2**：WHEN 同一用户同一自然日多次请求 `/today`，THE 系统 SHALL 返回同一 prompt 与同一 session。 · 测法：两次 GET 的 id 相同。
- **AC-I3**：WHEN `winnerType=A`，THE 系统 SHALL 返回 ≤3 个**均带可播放音频**的词（预挂或 TTS 降级）。 · 测法：每个 retryItem 有可播 url。
- **AC-I4**：THE 导入 SHALL 支持一次导入 ≥21 道合格题，并使随后 21 个日历日均能出题。 · 测法：种子 + 日期模拟。

**NFR（MVP）**

| 维度 | 要求 | 依据 |
|---|---|---|
| 首页→可录音 | ≤10s（含首次授权） | E17-4 |
| P2→P3 | 目标 8s / P95 15s；**超 20s 触发降级提示（AC-S10）** | E2、E7 |
| **弱网降级**（v1.1 新增） | **评分链路变慢但未报错时不得让用户无提示等待** | E2（等待即流失）；对照 AC-S6 只覆盖"报错"场景的缺口 |
| 会话预算 | 8 分钟（含热身+再试） | E9 |
| 规模 | 小流量验证（百～千学生） | E16 |
| 鉴权 | 邮箱一次性码 + 自有 token；运营与学生隔离 | E17-3 |
| 隐私 | 音频按用户隔离；**不做声纹** | 声纹属 Future 课堂 |
| 成本 | 每会话 ≈1 次 ASR + 1 次短 PA + 1 次小 LLM 分类 | 同步可承受 |
| 可观测 | 埋点：授权、开始说、出下一步、再试/跳过、收工、失败、**降级（degraded_flag）** | 支撑成功标准 1–4 |

# 第二部分：Next（主循环验证之后）

**进入条件**：MVP 达成内部 D1 回访基线，且 **再试率（含跳过率倒数）** 证明学生真的在用 P3。依据 E9、E15：先证明主循环，再加功能。

Next 只补 MVP 刻意留下的四个缺口：**忘 / 浅 / 孤 / 信**（第四个「信」为 v1.1 新增）。

# 第三部分：Future（护城河，不进前两刀）

进入条件：Next 的复习与问答已被真实使用。依据 E16。

## 9. Future 学生端

| 功能 | 为什么以后才做 | 怎么做（方向） |
|---|---|---|
| **1 人 vs 3 AI 短讨论**（可选 DSE 包） | E11 是应试刚需，但对泛学生（E17-1）太重，会破坏 8 分钟收工 | 独立「挑战/考试」入口或每周一次，**不替换** `/today` |
| **教室一麦四人出分** | E6 属老师/课堂场景，非日常主循环 | 独立多人语音管线 + 说话人分离；学生端只收个人报告 |
| **互动标签**（发起/回应/打断） | 讨论真正的失败点是互动不是音素（E11 vs E7） | utterance 分类；反馈仍是一句人话 |
| **辩论后论证树** | E14 偏思考力，不是每日开口 | 按需嵌入，不进首页 |
| **课中词进日练** | E13 同传无差异，抽词有 | 课后把词推进 ReviewItem |
| **口音选择**（v1.1 新增） | E18：SpeakShark 已用美/英/澳/加口音做卖点；MVP/Next 阶段泛学生更需要"被听懂"而非"选口音"，但长期看这是可感知的差异化点 | Word 表加 `accent` 字段；示范音按口音分组；不影响 A/B/C 判定逻辑 |

Future 仍守 **首页一条路**：应试/课堂是加成，不是菜单墙（否则回到 E1）。

## 10. Future 基建

| 功能 | 为什么 | 怎么做 |
|---|---|---|
| 真 CMS（审核流、版本、内容包） | 学校要内容治理 | 把 Next 的导入工具升级，不推翻模型 |
| 班级 / 只读班报 | 卖进学校的前提 | 学生量足够后再接 |
| 说话人映射 UX（≤20s 认人） | 同机多人场景的教室摩擦点 | 依赖独立多人语音管线；学生日练不需要 |
| FSRS / 算法优化 | 复习量大了才值得 | 用 Next 的 SM-2 数据迁移 |
| 多口音示范 | ELSA 的单一美音是公认限制（E7） | word 加 accent 字段 |
| 第三方 / 手机号登录 | 邮箱即用的换机成本（4.4 妥协记录） | 账号合并策略先定 |

> **商业化路径待验证（v1.1 新增，不进上表，仅作方向性提示）**
> 全文档所有阶段都不做 Billing（§3），这个排除本身不变。但外部对标显示同类订阅定价集中在 **$8–20/月**（ELSA、Speak、Praktika 均已验证付费转化），本产品目前完全没有商业模式假设。建议：**Next 阶段结束、进入 Future 决策前，必须补一次商业化方向讨论**（哪怕结论是"继续免费+机构 To B"），避免在留存验证成功后，因为缺少方向判断而临时仓促定价，影响后续融资/汇报叙事。这不是新增范围，是防止"验证成功了但不知道然后要干嘛"的空窗。

## 11. 分阶段总图与依赖顺序

```
MVP    学生：今日一题 → 可选跟读 → 独白 → 一个下一步 → 再试/跳过 → 收工 → 7天模板句
       基建：Prompt + Word + Sentence + Session（含 degraded_flag） + 邮箱账号 + 21 题导入

Next   学生：复习插队 + 半双工问答 + 智能热身 + 完成日历 + 非阻塞信任背书
       基建：ReviewItem + 自动入队 + 抽检 + 题库 90 天 + QA 素材 + 候选 payload 保留

Future 学生：1v3 / 课堂一麦 / 互动分 / 课中词进日练 / 口音选择（首页仍一条路）
       基建：真 CMS + 班级 + 说话人 + FSRS + 多口音 + 更多登录方式
       方向：商业化路径讨论（不晚于 Next 结束）
```

**顺序理由**（学生循环定义基建，不是先建词库再找用户）
1. 先有会话与三选一反馈 —— 否则词句无处消耗。
2. 再有预挂词句 —— 否则 A/B 没材料。
3. 验证留存后才上 SRS 与问答（E10、E8）。
4. 最后才是课堂/应试大管线（E6、E11）。

## 12. 端到端验证步骤（MVP，真跑一遍）

1. 运营导入 21 道合格题（示范音 + 热身句 + ≥3 词 + ≥1 paraphrase），缺项应被拒。
2. 全新邮箱 → 收码 → 登录 → 直接落 `/today`（AC-S9）。
3. 首次点录音 → 授权 → 立即开录；埋点 `home_to_recording_ms ≤ 10000`（AC-S2）。
4. 不开热身，说 45 秒 → 同屏出现**恰好一个**下一步（AC-S3）→ 当屏再录（AC-S4）→ 见「今天练完了」。
5. 换一天：说完后**点跳过再试** → 仍标 COMPLETED，`retry_state=SKIPPED`（AC-S5）。
6. 当天再进 App → 不被强迫做第二题（AC-I2）。
7. 次日 → 出新题（轮转规则）。
8. 故意说得很不清 → winner=A，且 ≤3 个词都能播放（AC-I3）。
9. 评分接口注入 500 → 可重录，题不丢，当日资格保留（AC-S6）。
10. 完成 3 天后 `/me` 有非空模板句；构造 4A/2B/1C 校验文案与计数，并确认无 LLM 调用（AC-S8）。
11. **（v1.1 新增）** 评分接口注入 25s 延迟但最终返回 200 → 第 20s 出现降级提示，可选跳过直接 COMPLETED，`degraded_flag=true` 被记录（AC-S10）。

## 15. 竞品全景速查（v1.1 新增，供任务分解阶段快速对照）

| 产品 | 打法 | 最强点 | 最弱点 | 对本产品的启示 |
|---|---|---|---|---|
| ELSA Speak | 音素级纠音 | 反馈精度 | 真对话弱；2026 起新增模式选择增加了决策成本 | 纠音精度不必卷过 ELSA，卷"当屏可执行"（E7、E23） |
| Speak.com | AI 角色扮演对话 | 对话流畅度、场景丰富 | 反馈浅、自由对话常沦为"连环提问" | 对话深度是 Next 才补的缺口，MVP 不必比 | 
| Praktika | 头像式对话 | 开口心理门槛低 | 反馈深度不足、路径僵化 | 低门槛和深纠正难兼得，MVP 选择后者（E19） |
| Duolingo | streak + 游戏化 | 留存机制成熟 | 口语练习占比低 | streak 驱动的是"怕断"而非"想开口"，本产品刻意不做，但需数据验证（E20） |
| 英语流利说 | 关卡 + 配音课 + 多维打分 | 内容量大、打卡文化成熟 | 模块化重、多维分数不聚焦 | E4/E21 反面教材：不做关卡、不做多维分数 |
| SpeakShark | 纠音 + 对话 + 跨会话记忆 + 口音选择 | 正在缝合 ELSA+Speak 的空隙 | 尚新，规模/内容深度未知 | 最值得警惕的追赶者，本产品必须靠"更少但更狠"的单一动作取胜（E18） |
| Yoodli（相邻品类） | 多维沟通指标 | 指标丰富、适合职场场景 | 当屏不知道先改哪个 | 验证 principle 4：多维反馈牺牲可执行性（E22） |
